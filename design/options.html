  • 从"一份报告"变成"一个产品"：开源，读者可以提交自己看到的文章，也可以提交自己知道的来源（博客、实验室网站、订阅源）。

  • 有一个冲突要先说清：Product Hunt 和 HN 都靠投票排序，而投票正是"名人效应、AI 话题霸榜"的来源，试运行数据已经证明了这一点（原文中位数 593 分，回应中位数 2 分）。所以我建议借用它的"产品感"，但不用投票排序，公开信号用"回应数"和"编辑精选"，"收藏"只给个人用。

二、读者提交

提交分两种：一篇文章，或一个来源（博客、实验室网站、订阅源）。提交的东西先走同一套自动检查，再按规则决定是否需要人工审核。

实现方式读者要做什么我们要维护什么建议
GitHub Issue 表单需要 GitHub 账号，提交完全公开几乎为零；机器人读 issue，自动检查后开 PR第一版
网站内表单（Cloudflare Worker）不需要账号一个小接口和防刷验证；后台还是转成 issue 或 PR第二版
作者认领在自己网站放一个标记文件验证脚本；认领后作者可以改标签、合并重复第二版

所有提交和编辑决定都留在 git 里，这就是"开源"的部分：谁提交了什么、为什么收或不收，任何人都能查。

三、配色

每套只有一个品牌色，其余是中性色。对比度都按 WCAG 计算：品牌色文字在浅色和深色背景上都达到 4.5:1 以上，按钮文字也是。回应类型的四个颜色（反驳红、复现琥珀、扩展绿、讨论蓝）另外保留，所以品牌色最好避开这四个色相。

四、Logo

五个图形都和名字无关，可以配任何名字。每个都看了三种尺寸：大图、和字标并排、16 像素的浏览器标签图标。

五、名字

域名状态是 2026-11-06 用 RDAP / whois 查的，只说明"查不到注册记录"，最终能不能买、多少钱要以注册商为准。

六、需要你选

  1. 版式：同意"B 为主、C 的分支图、A 作紧凑视图"吗？
  2. 配色：选一套（或说想要的感觉，我再调）。
  3. Logo：选一个图形。
  4. 名字：选两三个你喜欢的，我再细查商标和重名。
  5. 不用投票排序，公开信号只用回应数和编辑精选。这一条你同意吗？
